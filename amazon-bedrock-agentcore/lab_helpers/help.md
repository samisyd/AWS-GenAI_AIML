

AWS STS stands for Amazon Web Services Security Token Service.   It is a specialized core web service designed to issue temporary, limited-privilege credentials (such as an access key ID, secret access key, and a security token) to users or applications.   

Instead of relying on permanent, long-term credentials (like a standard IAM user password or a hardcoded access key that never expires), STS allows you to swap them for short-lived credentials that automatically expire anywhere from 15 minutes to 36 hours later.  


 Key Features of AWS STS
 
 Ephemeral Access: Because tokens expire automatically, they significantly reduce the security risk of credential leakage or "secret sprawl".  
 
  No Permanent Storage: The temporary credentials generated by STS are not saved against an IAM user account. Once they expire, they are completely dead and cannot be reused.   
  
  Granular Control: You can attach extra restrictions or session policies when requesting temporary tokens to further narrow down what the token is allowed to do.Common Ways STS is Used
  
  IAM Role Assumption (sts:AssumeRole): As seen in your script, services or users call STS to temporarily "step into" an IAM role to inherit its specific permissions for a task.
  
  Cross-Account Access: Allowing a trusted identity from one AWS account to temporarily access resources in another account without needing permanent login profiles there.   
  
  Identity Federation / Single Sign-On (SSO): When external users log into AWS using corporate credentials (like Okta, Google Workspace, or Active Directory), STS generates their temporary console session.
  
  Application and Container Workloads: Giving backend services (like EC2 instances, Lambda functions, or container tasks) dynamically generated tokens so they can securely talk to other AWS services like S3 or Bedrock without hardcoding keys into code.



  AWS SSM stands for AWS Systems Manager (formerly known as Simple Systems Manager).

It is an operations management service that helps you manage, monitor, and automate your infrastructure (such as EC2 instances, virtual machines, and on-premises servers) at scale. Instead of logging into servers individually using SSH or RDP, Systems Manager acts as a centralized control center for your operational tasks.

Core Capabilities of AWS SSM

AWS SSM is broken down into several key feature groups:
1. Operations Management & Dashboards

    OpsCenter: A central place for operations engineers and IT pros to view, investigate, and resolve operational issues (OpsItems) related to AWS resources.

    Explorer: A customizable dashboard that provides a visual summary of your operations and resource inventory across AWS accounts and regions.

2. Application Management

    Parameter Store: A widely used feature that provides secure, hierarchical storage for configuration data management and secret management (like database connection strings, API keys, or passwords). It integrates with AWS KMS for encryption.

    Application Manager: Helps you analyze and manage the operations of your applications in a single console.

3. Change Management

    Automation: Simplifies the creation of automation workflows to perform common IT and development tasks, such as AMI patch updates, database backups, or incident remediation.

    Change Calendar: Allows you to set up blackout periods where certain changes (like deployments) are blocked or restricted.

4. Node Management (Fleet Management)

    SSM Agent: A lightweight software agent installed on your EC2 instances or hybrid servers that allows Systems Manager to communicate with them.

    Session Manager: A secure and auditable node management capability that lets you connect to your instances via a browser-based shell or the AWS CLI. It eliminates the need to open inbound SSH/RDP ports or manage bastion hosts/jump boxes.

    Run Command: Allows you to run scripts or configuration commands across multiple instances simultaneously.

    Patch Manager: Automates the process of patching operating systems with security updates.

    Inventory: Automatically collects metadata (installed software, OS versions, etc.) from your managed instances.

Why Do Developers and DevOps Engineers Use SSM?

    Security: Session Manager removes the risk of leaving port 22 (SSH) open to the internet.

    Centralized Secrets & Configs: Parameter Store is a lightweight, cost-effective (free for standard parameters) alternative to storing environment variables, configuration settings, or API secrets securely.

    Automation: It takes the manual labor out of routine maintenance, patching, and scaling operations.
